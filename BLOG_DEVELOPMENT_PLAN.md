# Rasa Ecology Blog Development Plan

## Summary

Build a static SEO blog for `rasaecology.com` where Edwin writes in Notion, while the public website is generated by Astro and hosted on GitHub Pages.

Chosen defaults:

- CMS/writing interface: Notion database
- Public site: Astro static blog
- Hosting: GitHub Pages
- Publishing: scheduled GitHub Actions sync from Notion
- Media handling: download Notion images during build, convert/compress to WebP, store in repo/public build output

Estimated MVP: **4-6 working days**

## Implementation Plan

### 1. Project Setup — 0.5 day

Create a new Astro project in `/Users/deekshith/Desktop/99-projects/rasa/blogs`.

Add:

- Astro content collections for blog posts
- TypeScript
- RSS feed
- sitemap
- basic SEO metadata
- GitHub Pages deployment config
- GitHub Actions workflow

Acceptance criteria:

- `npm run dev` opens a working blog locally
- `npm run build` produces a static site
- GitHub Pages can serve the generated site

### 2. Blog Layout and SEO System — 1 day

Build the public blog UI once, since layout will not change often.

Pages:

- `/` or `/blog`
- `/blog/[slug]`
- `/authors/[author]`
- `/tags/[tag]`
- RSS feed
- sitemap

Post fields:

- title
- slug
- description
- author
- status
- tags
- published date
- updated date
- hero image
- canonical URL
- OpenGraph title/description/image

Design direction:

- Clean editorial layout
- Fast-loading pages
- Strong typography
- Good mobile reading experience
- Product-adjacent but not sales-heavy

Acceptance criteria:

- Every published post has title/meta description/OG tags
- Blog pages pass basic mobile layout checks
- RSS and sitemap include published posts only

### 3. Notion Database Setup — 0.5 day

Create a Notion database named `Rasa Blog Posts`.

Required properties:

- `Title` — title
- `Slug` — text
- `Status` — Draft, Ready, Published, Archived
- `Author` — select, initially Edwin and Deekshith
- `Description` — text
- `Tags` — multi-select
- `Published Date` — date
- `Updated Date` — date
- `Hero Image` — files/media
- `SEO Notes` — optional text
- `Target Keyword` — optional text

Publishing rule:

- Only posts with `Status = Published` are included in the public site.
- Draft and Ready posts stay private in Notion.

Acceptance criteria:

- Edwin can create a page and write using normal Notion blocks
- The database has enough structured fields for SEO generation
- The Notion integration token can read the database

### 4. Notion-to-Astro Sync Script — 1.5-2 days

Build a sync script that runs in GitHub Actions and locally.

Behavior:

- Fetch all Notion database rows with `Status = Published`
- Convert Notion page blocks into MDX or Astro-compatible Markdown
- Generate one file per post under Astro content
- Preserve headings, paragraphs, lists, quotes, tables where practical
- Convert Notion bookmarks/videos into embed blocks where supported
- Skip unsupported blocks with a visible build warning

Generated post shape:

```mdx
---
title: "How Compost Improves Soil Ecology"
slug: "compost-soil-ecology"
description: "Learn how compost supports microbial life..."
author: "Edwin"
publishedAt: "2026-05-29"
updatedAt: "2026-05-29"
tags: ["compost", "soil"]
heroImage: "/uploads/compost-soil-ecology/hero.webp"
targetKeyword: "compost soil ecology"
---

Post body...
```

Acceptance criteria:

- A published Notion page becomes a working blog page
- Slug conflicts fail the build clearly
- Missing required fields fail the build clearly
- Draft posts are not generated

### 5. Image Pipeline — 1 day

Add image handling inside the sync/build pipeline.

Behavior:

- Download Notion-hosted images during sync
- Resize large images to sensible widths
- Convert images to WebP
- Store images under `public/uploads/[post-slug]/`
- Replace Notion image URLs with local optimized image paths
- Preserve alt text/captions where available

Default sizes:

- Hero image: max width 1600px
- Inline image: max width 1200px
- Thumbnail/social image: generated from hero where possible

Acceptance criteria:

- Blog does not depend on expiring Notion image URLs
- Large images are compressed before publishing
- Broken image downloads fail the build with a clear message

### 6. GitHub Actions Publishing — 0.5-1 day

Create a scheduled workflow.

Behavior:

- Runs on a schedule, default every 6 hours
- Can also be triggered manually
- Pulls from Notion
- Generates content and images
- Builds Astro
- Deploys to GitHub Pages

Required GitHub secrets:

- `NOTION_TOKEN`
- `NOTION_DATABASE_ID`

Acceptance criteria:

- Manual workflow run publishes a Notion post
- Scheduled workflow works without local machine involvement
- GitHub Pages serves the latest published content

### 7. Writer Workflow Guide — 0.5 day

Create a short guide for Edwin.

Workflow:

1. Open Notion database
2. Create new post
3. Fill title, slug, description, tags, hero image
4. Write article in Notion
5. Set status to `Published`
6. Wait for scheduled publish or ask Deekshith to run workflow manually

Add guardrails:

- Keep slugs lowercase with hyphens
- Use one H1 only through the title field
- Use H2/H3 inside article body
- Add image captions where helpful
- Add target keyword before publishing

Acceptance criteria:

- Edwin can publish without touching GitHub
- The workflow is understandable in under 10 minutes

## Test Plan

Functional tests:

- Published Notion post appears on the blog
- Draft Notion post does not appear
- Missing title/slug/description fails clearly
- Duplicate slug fails clearly
- Image uploads are downloaded and converted to WebP
- YouTube/video embeds render correctly
- Tags and author pages generate correctly

SEO tests:

- Each post has title, meta description, canonical URL, and OG tags
- Sitemap includes all published posts
- RSS includes recent published posts
- URLs are stable and clean
- Lighthouse check passes basic performance/accessibility/SEO standards

Workflow tests:

- Edwin can create a post from Notion only
- Manual GitHub workflow run publishes successfully
- Scheduled workflow publishes without local machine involvement
- Broken Notion image or unsupported block produces understandable logs

## Assumptions

- The project starts from an empty directory.
- GitHub Pages remains the hosting target.
- Notion is the only writing/admin interface for v1.
- No custom browser admin will be built for v1.
- GitHub Actions scheduled sync is acceptable; instant publishing is out of scope for v1.
- Videos will be embedded from YouTube/Vimeo or similar, not uploaded directly to GitHub.
- The public blog layout will be controlled in Astro, not Notion.
